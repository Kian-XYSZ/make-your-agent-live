# 01 · 接进 QQ

> 这是整个项目**最容易卡住**的一步。按顺序走，别跳。

---

## 为什么必须用协议端

QQ 的语音消息是 **SILK 编码**——腾讯自己的格式。

```
ffmpeg -decoders | grep silk     →  （空）
ffmpeg -i voice.amr out.wav      →  Invalid data found
```

而且那个 `.amr` 后缀是**骗人的**，文件头实际是 `#!SILK_V3`。

所以：**普通客户端拿不到可用的语音文件，必须用协议端。**

| 协议端 | 状态 | 说明 |
|---|---|---|
| **SnowLuma** | ✅ 推荐 | 本项目全程验证过，Windows 有现成包 |
| NapCat | ❌ 停止维护 | README 现在只剩一句"到这里告一段落" |
| Lagrange | 可用 | 未验证 |

---

## 你需要两个 QQ 号

| 号 | 角色 |
|---|---|
| **大号** | 你平时用的，和她聊天的那一个 |
| **小号** | 当机器人，**建议新注册**，别用大号 |

> 用小号的原因：协议端会登录这个号，有被风控的风险。大号被封代价太大。

---

## 第 1 步：装 SnowLuma

1. 下载 Windows 发行包（`SnowLuma-vX.Y.Z-win-x64.zip`）
2. 解压到**不含中文和空格**的路径，例如 `C:\SnowLuma`
3. 里面自带 `node.exe`，不用另外装 Node

## 第 2 步：配 OneBot

编辑 `config/onebot_<小号>.json`，确认三件事：

### ① HTTP 服务（给 `myal qq` 用）

```json
{
  "httpServers": [
    { "name": "http-default", "host": "127.0.0.1", "port": 3000, "accessToken": "" }
  ]
}
```

### ② WS 客户端（给宿主网关用）

如果你用 DSH 的 qq-gateway 插件：

```json
{
  "wsClients": [
    {
      "name": "gateway",
      "url": "ws://127.0.0.1:8792/onebot",
      "accessToken": "<网关的 token>",
      "messageFormat": "array",
      "reconnectIntervalMs": 5000
    }
  ]
}
```

`messageFormat` 必须是 `array`——字符串格式（CQ 码）在语音/图片上好出错。

### ③ 自动挂载（**最容易漏的一步**）

编辑 `config/runtime.json`：

```json
{ "hookAutoLoad": true }
```

**必须改成 `true`。**

默认是 `false`，意味着 SnowLuma 只在启动时挂载一次 QQ 进程。
**QQ 一重启，连接就断了**，而且日志看起来一切正常——这个坑能让人查半天。

改完之后，SnowLuma 会持续发现新的 QQ 进程并自动挂载。

## 第 3 步：启动并扫码

```bash
node .\index.mjs
```

WebUI 在 `http://127.0.0.1:5099`（默认用户 `admin`，密码首启生成）。

**扫码这一步必须你本人做。** 任何 agent 都不能代替。

## 第 4 步：验证

```bash
myal qq status
```

期望：

```
✔ 已连接  QQ 1234567 (昵称)
```

如果失败，按顺序查：

| 现象 | 原因 |
|---|---|
| 连不上 3000 | HTTP 服务没开，或端口被占 |
| 401 / 403 | `accessToken` 对不上 |
| 连上了但收不到消息 | `hookAutoLoad` 是 `false` |
| QQ 重启后掉线 | 同上 |

## 发语音 / 发图片

```bash
myal qq send --record out.wav --to 123456
myal qq send --image chart.png --to 123456
myal qq send --text "纯文字" --to 123456
```

### 一个必踩的坑：用 `path` 不是 `file`

如果你在 DSH 里用 `qq_send` 工具发语音：

```
❌ { type: 'record', data: { file: '/path/x.wav' } }
   → 非主号回合不允许发送 file 标识内容（防本机文件转码外发）

✅ { type: 'record', data: { path: '/path/x.wav' } }
```

`file` 是"裸标识"，被安全策略拦；`path` 才走"网关自己读文件 + 转 base64"的正路。

另外网关的 `fileSendPolicy` 限制了只能发 **outbox 目录**里的文件：

```
~/.dsh/storages/qq-gateway-outbox/
```

本项目在 DSH 里的 `tts` 工具会**优先写进这个目录**，所以不用手动拷。

## 收语音（反方向）

协议端把语音消息推给你时，消息段长这样：

```json
{ "type": "record", "data": { "file": "abc.amr", "url": "https://..." } }
```

拿到 `file` 之后：

```bash
# 让协议端转成 wav（它内部有 SILK 解码器）
# OneBot 动作：get_record(file, out_format="wav") → { base64 }

# 然后转文字
myal asr /tmp/voice.wav
```

两条路都可以：

| 方式 | 说明 |
|---|---|
| `get_record` 动作 | 协议端直接给 wav 的 base64，最省事 |
| 下载 `url` | 拿到的是 SILK，得自己解，**不推荐** |

> DSH 用户：`qq_action` 可以直接调 `get_record`。

## 安全建议

个人号用协议端有风控风险。这几条能显著降低概率：

| 做法 | 理由 |
|---|---|
| 只用小号 | 大号被封损失太大 |
| **不开群** | 群里刷屏最容易触发风控 |
| 限制频率（每分钟 ≤6 条） | 机器人才会秒回 |
| 加拟人延迟（1–15 秒） | 同上 |
| 只允许主号私聊 | 陌生人发消息不回复 |

配置项在网关插件的 `rateLimitPerMinute`、`replyDelayMode`、`allowAllPrivate` 里。
